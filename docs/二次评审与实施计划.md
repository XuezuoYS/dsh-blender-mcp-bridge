## 2. 要纠正的说法（文档小修，不影响路线）

**A. `engines.dsh` 不是“必须精确版本”，不匹配也不是“完全静默”。**
rc.2 的 `dsh-app-boot` 用 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })` 判定：写范围能匹配，写精确预发布也能匹配。不匹配时，组合包（`dsh.profile.bundles` 里的）会被跳过并列入 `skippedBundles`，普通插件行会变成 `disabled: true` 并报告包名/版本/风险；另外还有 `dsh plugin allow-version` 的精确版本豁免可以救。所以“写范围就失效”是错的，“跳过但没有醒目报错”这个提醒仍然成立。
建议改成：“`engines.dsh` 用精确版本最省事（rc 漂移时不用反复调范围）；写范围也能匹配。不匹配的组合包会被跳过（`skippedBundles`），行级插件会被禁用并报告，可用 `dsh plugin allow-version` 精确豁免。”——`技术路线.md` §3 模块表和 `可行性评估.md` §3.1 各改一句。

**B. `screenshot_window` 改成“不可用”，不是“不存在”。**
5.2.2 里 `bpy.ops.screen.screenshot_window` 这个属性名在，但 RNA 没注册，调用会失败。文档 §4.5 的结论不变，把“不存在”改成“未注册、调用即失败”更准确。

**C. `dsh.manifestVersion: 1` 是可选字段。**
`dsh-package-manifest` 的说明是“manifest 格式标识，声明的格式为 1”，没声明也能用。建议写成“建议声明”，不要写成硬性要求。

**D. 架构图漏了 `lib/tools.js`。**
`技术路线.md` §2 的架构图里有 12 个 lib 文件，§3 模块表多出 `lib/tools.js`（八个工具的领域逻辑）。补进图里，免得读者以为工具逻辑散在 `index.js`。

**E. 引擎参数以运行时枚举为准。**
`技术路线.md` §4.6 写 `BLENDER_EEVEE` 或 `CYCLES`，实测工厂启动只枚举出 `BLENDER_EEVEE`。CYCLES 是否出现取决于用户是否启用 Cycles 插件。建议加一句“按 `status.renderSettings.engine` 回传当前值，不硬编码引擎名”。

## 3. 设计缺口（开工前补进文档）

按“必须补 / 建议补”两级。每条的落点都写清楚。

### 3.1 必须补

**① 回滚路径（最重要）。已拍板：保守版。**
新文档把 `wm.open_mainfile` 列进拦截名单，同时**不提供**恢复工具。按主人决定：**AI 不得自行回滚**——发现异常只告知用户并结束本轮，回滚由用户手动完成（`Ctrl+Z` 或自己打开快照）。实现上不新增 `restore` 工具，快照只写不读。

**② 拒绝态接管提示（旧 I7 教训）。**
`exec` 被静态检查或守卫拦下时，返回里要有“为什么拦 + 可以怎么写”的替代路径（例如越界写时给出任务目录里的合法路径），不能只给 `PermissionError` + `blocked[]`。否则模型会反复试探同一路径，刷噪声。
建议 `blender_mcp_exec` 的 `blocked` 返回增加 `suggestedPath` 字段；写进 §4.3 的返回列表。

**③ 超时语义。**
`responseTimeoutMs` 默认 30 s。到点后 socket 断了，但 Blender 主线程可能还在跑那段代码，之后照样会 `undo_push`——Node 侧却已经把这次调用记成超时，快照/审计/undo 对不上。
建议明确：超时返回 `timeout` + 明确说明“代码可能仍在 Blender 中执行”；下一次 `status` / `exec` 开头做一次轻量自检（dirty、`.blend` mtime、对象数），并在结果里提示“上一轮可能超时”。写进 §4.3 / §5。

**④ 并发写锁。**
模型可能并行调用两个写工具（两条连接）。Blender 主线程是串行的，但 Node 侧的“快照 → 执行 → 审计”顺序会被打断。
建议：Node 侧对写类工具（`exec` / `snapshot` / `capture` / `render` / `helper`）加一把进程内互斥锁；只读工具不锁。写进 §5。

### 3.2 建议补

**⑤ 配置语义写清楚。**
- `taskRootMode` 与 `taskRoot` 的优先级没定义：`taskRoot` 非空时是否无视 `taskRootMode`？建议写成“`taskRoot` 非空 = 固定根目录，忽略 `taskRootMode`”。
- `guard.enabled = false` 到底关什么？L1 静态检查？L2 运行时守卫？`undo_push`？建议写成“只关 L2 运行时守卫；L1、快照、undo、审计仍生效”，或者干脆删掉这个键（少一个死配置）。

**⑥ 快照体积。**
配置里没有体积上限。大工程 × 3 代可能很占盘。上一轮有过 `maxBytes` 告警的思路。建议至少“单代超过阈值时 warning”，或者明确写“v1 不做，靠用户自己清”。

**⑦ 维护类 helper 的“确认”机制。**
`helper-runtime.md` §8 第 9 条写“打开开关后可列出但运行前仍要确认”，但没定义“确认”是什么。建议二选一：删掉这句；或在 `blender_mcp_helper` 结果里返回“维护类 helper 会改技能库文件，请用户确认后再运行”。

**⑧ 多会话复用任务目录。**
属主标记 `.dsh-blender-task.json` 记了 `sessionId`，但“另一个会话遇到同名任务目录、标记存在”时是复用还是换名，没写。建议：标记存在且 `sessionId` 不同时，也追加 `-2`，避免两个会话往同一个目录里写。

**⑨ 技能注册规模（v1 定案）。**
`技术路线.md` §15 把“注册 1 个编排技能还是 30 个领域技能”留作待定。建议 v1 就定成：**只注册 1 个 `blender-live-session` 编排技能**，其余内容随包放 `references/`，模型按需读；等工具、截图/渲染、护栏稳了再扩。

**⑩ `inject` 里不放 `attachments` / `llm`（可选注入）。**
cordis 的 `inject` 是“服务全齐才激活”：缺 `attachments` 或 `llm` 时整个插件会一直等待、不报错。这两个服务只在 capture/render 的图片块和能力判断里用得上，建议改成 `ctx.get('attachments')` / `ctx.get('llm')` 可选获取；拿不到时降级为“只返回路径”，插件本体照常加载。

### 5.4 M0 复测清单

- 撤销：一次 exec 一次 `undo_push` = 恰好 1 个 Ctrl+Z 步骤；异常路径也 push；编辑模式会弹回对象模式。
- 守卫：模块级 `bpy.ops` 代理能拦 `save_mainfile` / `save_as_mainfile` / `open_mainfile` / `quit_blender`；`_op_create_function` 读写透传；重装剥旧钩子；根目录变化强制重装。
- 快照：`copy=True` 不改 `filepath`、不清 dirty、不生成 `.blend1`；压缩确实更小更快；未保存工程也能存。
- 截图：整窗截图落盘（绝对路径 + `.png`）；后台模式 `poll failed`；首次/稳定耗时。
- 渲染：按显式参数出图；`finally` 还原后 diff 为空；冷 Shader 缓存首次约 17 s；`BLENDER_EEVEE` + `eevee.taa_render_samples` 可读写。
- Python：3.10+ 探测、缺依赖报缺失模块（不抛裸 traceback）。
- DSH 侧：`defineTool` 注册、图块形状、`inputModalities` 判断、`turn/start` 订阅、`skills.register` 最小验证。
