# 可行性评估：DSH 接入 Blender 活会话

> 日期：2026-10-18
> 结论先说：**技术路线成立，可以做。** 但有两条必须先接受的事实：
> 1. 这**不是沙箱**——真正能防的只有“误操作”，防不住刻意绕过；
> 2. 知识库只给**英文官方手册**：中文页正文是网页脚本加载的，`web_fetch` 抓不到；模型侧不展示中文，英文就够用。

---

## 1. 结论一览

| 能力 | 判断 | 一句话 |
|---|---|---|
| DSH 插件接入 | ✅ 可行 | host 插件就是 ESM 包 + `apply(ctx, config)`，工具用 `defineTool` 注册 |
| 连用户正在编辑的 Blender | ✅ 可行 | 官方 add-on 在 `127.0.0.1:9876` 开 TCP，协议只有 `execute`，已实测连通 |
| 改动进撤销历史、Ctrl+Z 逐步回退 | ✅ 可行 | 每次 exec 末尾 `bpy.ops.ed.undo_push()`，实测正好等于 1 个撤销步骤 |
| 绝不保存用户会话 | ⚠️ 只能“强约束” | add-on 完全不拦保存，必须由插件自己拦（代理 + 文件钩子 + 事后审计）；不是沙箱 |
| 任务目录 `.dsh-blender-*` | ✅ 可行 | 从 `bpy.data.filepath` 取工程目录；未保存工程落 DSH 会话 workspace |
| 快照默认 3 代 | ✅ 可行 | `save_as_mainfile(copy=True, compress=True)` 不改当前路径、不清 dirty，实测 9–90 ms |
| 截图与视觉反馈 | ✅ 可行 | 整窗截图 + 可控预览渲染；图片块与参数还原已实测 |
| Helper 与分析 Python | ✅ 可行 | 23 个常规 helper + 3 个维护类；Node spawn 独立 Python，不依赖 `dsh-blender` |
| 官方文档知识库 | ✅ 可行（限英文） | `en/5.2` 能抓、`zh-hans/5.2` 正文抓不到；模型侧只用英文 |
| 与 `dsh-blender` 共存 | ✅ 可做到“不打架” | 插件/包/id 全局统一 `dsh-blender-mcp-bridge`；工具用 `blender_mcp_*`，与 `blender_*` 错开 |

**总体判断：值得做，且旧实现已经把最难的路探过一遍。新方案应“瘦身重写”，不是从零猜。**

## 3. 逐项可行性

### 3.1 DSH 插件接入 ✅

rc.2 的 host 插件没有构建负担：

- 一个 ESM 包，具名导出 `name` / `inject` / `Config` / `apply(ctx, config)`；
- `package.json` 写 `dsh.manifestVersion: 1` 和 `dsh.bundle.patch`；
- 工具用 `ctx.tools.register(defineTool({...}))` 注册，schema 自动进模型工具表；
- 提示词用 `ctx.systemPrompt.section()` 注册；
- 包不需要浏览器端，纯 host 插件即可。

**唯一的硬坑**：`engines.dsh` 要和运行版本对得上（本机 `"0.2.1-rc.2"`）。精确版本最省事，写 SemVer 范围也能匹配；不匹配的组合包会被跳过（`skippedBundles`）、行级插件会被禁用并报告，还可以用 `dsh plugin allow-version` 精确豁免——但别指望用户会去翻这些提示，所以默认写精确版本。

### 3.2 连活会话 ✅

官方 add-on 的“MCP”名字有误导：它没有 MCP 协议，只有一条私有套接字。

- 帧格式：UTF-8 JSON + 单字节 `0x00`；
- 请求：`{"type":"execute","code":"...","strict_json":true}`；
- 一次连接只处理一个请求，响应后 add-on 主动断开；
- 代码在 Blender 主线程执行，**不会自动 `import bpy`**，必须自己写；
- 所谓弱沙箱只拦 `sys.exit` 和 4 个 `wm.*` 算子，保存、文件读写、联网都不拦。

旧的 MCP server 不需要运行；我们直接说 add-on 的套接字，少一层不受管的执行路径。

### 3.3 撤销 ✅（本次最关键的实测）

在 GUI 交互模式下：

- 一次 exec 里无论调多少算子、直接改多少属性，**末尾一次** `bpy.ops.ed.undo_push()` 就压出**正好一个** Ctrl+Z 步骤；
- 不 push 就完全没有撤销步骤（算子里自带的 push 在 timer 回调里不生效）；
- push 会把 `bpy.data.is_dirty` 置 True，正好符合“用户能看到有未保存改动”的语义；
- 默认撤销栈 32 步，连续 push 不合并；
- 撤销会把用户从编辑模式踢回对象模式，这是 Blender 自身行为，插件应提前告知。

结论：**“每次 AI 写操作占一个撤销步骤”成立。** 实现上只需保证“末尾 push”在 `finally` 里，异常时也压栈，别让半截改动变成不可撤销。

### 3.4 不保存 ⚠️

这里必须说清楚：

- add-on **完全不拦保存**。实测 `bpy.ops.wm.save_mainfile()` 直接把文件写盘，还生成 `.blend1`；
- exec 里 `open()` 写文件也畅通无阻；
- 给 `bpy.ops.wm.save_mainfile` 赋值不生效；改 `_op_create_function` 只活一次 exec；
- 但**把整个 `bpy.ops` 换成模块级代理**是可行的：旧实现实测过，本次也在真实 add-on 套接字里复测了——代理安装后调 `save_mainfile` 抛 `PermissionError`，目标文件没有生成；它能拦住 `save_mainfile` / `save_as_mainfile` / `open_mainfile` / `quit_blender` 等；
- 再配合 `builtins.open` / `io.open` / `os` / `shutil` / `pathlib` 的写删钩子，可把文件写入限制在任务目录内。

**诚实边界**：这些都是“防手滑”，不是安全沙箱。AI 如果刻意用 `importlib.reload`、`ctypes`、拼字符串调 C，仍可能绕过。上游官方页面自己就写“没有任何防护，建议用虚拟机”。本插件只能在提示词、静态拒绝、运行时守卫、事后审计四层上把误操作概率压到最低。

另外建议每次 exec 前后对用户 `.blend` 做一次 mtime/size 对比；真被保存了，至少能立刻报出来（不能悄悄当没事）。

### 3.5 快照 ✅

`bpy.ops.wm.save_as_mainfile(filepath=..., copy=True, compress=True)` 实测：

- 不改当前 `bpy.data.filepath`；
- 不清 `is_dirty`；
- 未保存工程（filepath 为空）也能存；
- 不生成 `.blend1`；
- 小场景未压缩 507 KB / 21 ms，压缩后 95 KB / 9 ms；GUI 下约 86 ms；
- 存的是**内存里的当前状态**，包括还没 push 的改动。

所以“任务目录里默认留 3 代快照”在机制上没问题；代次可配置（默认 3，范围 1–20）。要注意两点：快照是完整 `.blend`，外部贴图/链接库没打包就不在快照里；大工程耗时和体积还没压测。

### 3.6 任务目录 ✅

- 当前工程路径从 `bpy.data.filepath` 取；已保存工程就是完整路径；
- 未保存工程是空字符串，没有“当前目录”。按主人决定，这种情况落到 DSH 会话 workspace，并在返回里明确说明“工程未保存，快照/产物在 workspace”；
- 目录名 `.dsh-blender-{任务名}` 在 Windows 上只是普通名字（点开头不等于隐藏属性）；
- Node 侧建目录、轮换快照比在 Blender 里做更简单；路径统一由插件派生绝对路径（Blender 进程的 cwd 在 `Program Files`，相对路径会落错地方）。

### 3.7 知识库 ✅（限英文）

AGENTS 写的是 `https://docs.blender.org/manual/zh-hans/{版本}/`。实测：

- `en/5.2/` 和 `zh-hans/5.2/` 都返回 200，5.2 就是当前最新版；
- **英文页是静态文本，`web_fetch` 能抓到完整章节；中文页正文走 JS 加载，抓回来基本是“语言 / 加载中...”，深层页只剩版权行**；
- 版本号从 `bpy.app.version_string`（实测 `"5.2.2 LTS"`）取 `major.minor`，即 `5.2`。

按主人决定：**模型侧只用英文页，不做中文展示**；文档是给模型知道怎么操作的，英文足够。中文链接不再返回给模型。

### 3.8 与 `dsh-blender` 共存 ✅（有版本风险）

`dsh-blender` 走完全不同的模型：

- 每个操作 spawn 一个 `--background` Blender 进程；
- 不开控制端口，不要求官方 add-on；
- `blender_python` 等工具会**保存版本化 `.blend`**；
- 13 个工具：`blender_status`、`blender_scene_info`、`blender_object_info`、`blender_import`、`blender_python`、`blender_preview`、`blender_render`、`blender_render_frames`、`blender_export`、`blender_validate_scene`、`blender_validate_export`、`blender_helper_catalog`、`blender_helper_run`。

共存要点：

- **全局名称统一为 `dsh-blender-mcp-bridge`**（包名、插件 id、profile 条目）；工具名沿用 `blender_mcp_*`，不再另起一层新前缀，也不会和 `blender_*` 重名；
- **提示词必须写清分工**：活会话用本插件；磁盘文件分析/批量导出/离线验证用 `dsh-blender`；
- **它的技能链鼓励“保存版本化 .blend”**，与本项目“禁止保存活会话”直接冲突，必须在提示词里压住；
- 它看不见用户未保存的改动，两边同时操作同一工程会产生语义分叉；
- 它声明的 DSH 兼容范围是 `0.2.0-rc.2` / `0.2.1-alpha.1` / `0.2.1-alpha.2`，**没有 rc.2**。本机 rc.2 上它能否正常加载，需要实测；如果不行，是上游兼容问题，不是本插件造成。
- 本插件的技能和 helper **直接引用 `create-3d-model` 上游**，不复制 `dsh-blender` 的文件；`dsh-blender` 只作为工具映射和共存方式的参考。

端口方面反而是好消息：它不开 9876，所以不会抢端口。真正的坑在 Blender 自己——**Windows 上两个 Blender 可以同时监听 9876**，连接会被先启动的实例接住，所以每次连接必须先握手（版本 + 文件路径 + dirty + 对象数）确认“连的是不是用户眼前那个会话”。

### 3.9 截图与视觉反馈 ✅

主人要求 v1 必须有：

- **整窗截图**：`bpy.ops.screen.screenshot(filepath=<绝对路径>)` 在 timer 回调里直接可用（`area=None` 也不需要 override），实测 1920×1009、551 KB、稳定 57–64 ms；后台模式一律 `poll failed`，所以截图只在活会话里做；
- **可控预览渲染**：`bpy.ops.render.render(write_still=True)` 同步出图，按用户给的宽/高/采样渲染；热渲染 0.11 s，但本机冷 Shader 缓存第一次 **17.2 s**，所以渲染工具超时要 ≥120 s；渲染不产生撤销步骤、不改 dirty、不改 filepath，改过的设置 `finally` 逐项还原；
- **不许 AI 自己改渲染参数**：提示词和工具描述都要写死“未经用户明确给出预览值，不要调整 `scene.render.*` / `scene.cycles.*` / `scene.eevee.*`”；用户说“用当前设置”就先读 `status.renderSettings` 原样回传；
- 渲染只写任务目录，路径用绝对路径 + 明确文件名；Blender 会自动建缺失父目录，所以写前必须用 `realpath + commonpath` 判定在任务目录内；
- 套接字回调里 `bpy.context.area` 是 `None`，所以视口/区域截图基本不可用；整窗截图是唯一稳定的窗口画面来源；`screenshot_area` 不加 `temp_override` 会静默写出 1×1 废图，`screenshot_window` 在 5.2 不存在；
- DSH 的图片块形状已确认：`{ type:'image', attachment:{ attachmentId, mediaType, bytes, width, height, name? } }`，先经 `ctx.attachments.saveImage({data, mediaType, name})` 落盘拿 ref；模型路由不支持 `image` 输入时会**静默退化成占位文本**，所以插件要自己判 `inputModalities.includes('image')`，不支持就只返回路径。图片限制：PNG/JPEG/WebP/GIF、单图 ≤20 MiB、单边 ≤8192 px、总像素 ≤64M px。

### 3.10 Helper 与独立 Python 链 ✅

v1 直接加入 `create-3d-model` 的 26 个 helper：

- 23 个常规 helper 进模型可调用面；3 个维护类随包保留、默认关闭；
- Blender 运行时 helper（`surface-texture-coverage-audit`）走插件内部 exec，只读、不 push；
- 其余 helper 由 Node `spawn` 独立的 `analysisPython` 子进程，只运行 catalog 内脚本；
- 依赖清单：numpy、Pillow、OpenCV、SciPy；`scripts/setupAnalysis.js` 创建 `.venv` 并安装；
- 不依赖 `dsh-blender` 的安装或 `.venv`；两边各跑各的；
- 安全边界：白名单脚本、结构化参数、输入限 workspace/任务目录、输出只落任务目录、超时、输出上限、维护类默认关闭。

这条链是 v1 明确接受的新增复杂度，换来的是参考图/线框/多视图/UV/外观 QA 的完整能力。详细设计见 [`helper-runtime.md`](helper-runtime.md)。

## 4. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 不是沙箱，动态绕过防不住 | AI 刻意操作仍可能保存/越界写 | 文档和提示词都如实说；四层防护只防误操作 |
| 多 Blender 实例抢 9876 | 连到错误的会话，改错场景 | 握手 + 状态里显示 filepath；多实例时让用户改端口 |
| 撤销栈只有 32 步 | 长会话早期步骤被挤掉 | 提示用户；重要节点用快照，不依赖撤销 |
| 大工程快照慢/大 | 每次写前卡顿、占盘 | 压缩、按轮快照、可配置份数；后续压测 |
| 主线程执行，UI 冻结 | 长代码/渲染时 Blender 卡住 | 单次 exec 控制在 30 s 内；长任务提示用 F12 或 deferred |
| 渲染写盘走 C 层 | 文件钩子拦不到渲染输出 | 渲染前检查 `scene.render.filepath` 必须在任务目录；改过的设置逐项还原 |
| 中文手册抓不到 | 模型查不到中文文档 | 按决定只用英文页，不返回中文链接 |
| DSH rc 版本频繁变 | `engines.dsh` 不匹配会静默不加载 | 精确 pin 版本；升级时按清单复核 |
| `dsh-blender` 与 rc.2 不兼容 | 共存失败、工具缺失 | 先实测；不兼容就只装本插件，或等上游更新 |
| 快照不含外部资源 | 恢复时贴图丢失 | 文档写明；需要完整包时另行打包 |
| 用户机器没有 Python 3.10+ | helper 不可用 | 明确报错和安装提示；不自动安装 |
| OpenCV/SciPy 安装体积大 | 首次 setup 慢、占盘 | 显式 setup；按 helper 报告缺失模块；纯 Python/Pillow helper 先可用 |
| helper 脚本 bug 写坏文件 | 任务目录被污染 | 输出限制在任务目录；脚本随包审查；不是沙箱 |
| Python 子进程注入/越界 | 执行非预期脚本或写盘 | 白名单 catalog、无 shell、参数校验、路径限制、超时、输出上限 |

## 6. 主人已拍板

| 问题 | 决定 |
|---|---|
| 安全防护范围 | 只守自己的工具，不做全局 guard |
| 失误处理 | AI **不得自行回滚**，只告知用户并结束本轮；插件不提供恢复工具 |
| 快照“自定义内容” | 指**快照代次**（默认 3，可配置） |
| 截图/视觉反馈 | 必须做：整窗截图 + 可控预览渲染 |
| 渲染参数 | AI 不得自行调整；按用户给的预览值渲染，改完必须还原 |
| 返回语言 | 面向模型的内容用英文；不做中文展示；文档给模型看操作方式 |
| 未保存工程 | 任务目录落到 DSH 会话 workspace |
| 命名 | 插件/包/id 全局统一 `dsh-blender-mcp-bridge`；工具沿用 `blender_mcp_*`，不再改名 |
| helper | v1 直接加入 23 个常规 helper + 3 个维护类（默认关闭）；自带独立 Python 链，不依赖 `dsh-blender` |
| 许可证 | MIT |
| 技能范围 | v1 只注册 1 个编排技能 `blender-live-session`，其余内容随包按需读 |
